# Security

Use a private channel to report a potential vulnerability to the repository owner. Include the affected version and a concise impact description, with testing limited to systems you control. Keep credentials, private readings and conversation data out of reports. If the owner has configured GitHub private vulnerability reporting, use that channel.

The [security architecture](docs/security.md) covers account roles, sessions, CSRF, credential use, private conversation ownership, broker trust and monitoring. The [release audit](docs/security-release.md) documents known dependency findings and the historical dump. The public [portfolio deployment](docs/deployment.md) exposes recorded data and optional bounded stateless inference.
